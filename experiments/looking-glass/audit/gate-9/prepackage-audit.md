## Blocking findings

1. **State-replacing events record the old after-state.** [`engine.mjs:12`](../../matched-observation/engine.mjs) keeps `const s=this.state`, then fingerprints `s` after its change callback. [`newChoice`](../../matched-observation/engine.mjs), [`restoreCheckpoint`](../../matched-observation/engine.mjs), and [`reopenSavedStart`](../../matched-observation/engine.mjs) replace `this.state`. Their event `afterFingerprint` and cursor therefore describe the discarded object. In three direct reproductions, each event's after fingerprint differed from the next event's before fingerprint without intervening clock movement. Fingerprint the current `this.state` after the callback and take cursor/condition fields from that same current state.
2. **Checkpoint-restored choice provenance has no declared source link.** Restoring checkpoint 2 reconstructs its first accepted choice in a temporary engine. Continuing to second 4 seals a trace whose envelope cites that temporary event ID, absent from the current session log; the envelope does not declare a canonical-run event source or a reconstruction event link. The current second choice does appear in the session. The first reference needs an honest, resolvable source, such as the frozen canonical run event identity or an explicit reconstruction record tied to the actual checkpoint restore. It must not be represented as a fabricated current-session user action.
3. **Actual controls can be mislabeled scripted demonstration and disrupt the tour.** On paused saved start, query buttons are enabled and call `engine.choose` directly ([`app.mjs:34`](../../matched-observation/app.mjs)). Two user-control clicks seal an envelope with `scripted_demonstration` provenance because the mode remains `saved-tour`; the reproduction records two `user-control` origins under that label. During a running tour, a query click neither pauses nor cancels the tour timer, allowing later scheduled choices to consume or reject the wrong budget. A user-origin query should enter exploration with an actual local-control trace and stop/pause canonical playback before mutation.
4. **Manual presentation controls can orphan a running tour.** The pause and restart handlers call `stopAny()` but do not mark `tourPaused` ([`app.mjs:80`](../../matched-observation/app.mjs)). Directly pausing the watch after tour second 6 leaves `tourPaused=false`. The timer is gone, while the state reports the tour playing. The same ownership path affects restart and other manual presentation actions; audit all manual controls while a saved tour owns the clock. Practice opening also leaves a running tour active, so it needs an explicit policy consistent with the frozen manual-exploration rule.
5. **A prior full export remains visible during an unfinished watch.** After a completed choose export, switching to watch leaves `#export-output` unchanged. Its full trace contains later occurrence records while the watch inspector and current card show only the prefix ([`app.mjs:86`](../../matched-observation/app.mjs)). Clear or replace stale completed-route output when entering an unfinished route. The public world table remains intentionally public; this finding concerns the instrument's own future trace payload.

These are contract fixes to mutable code; no frozen spec change is needed. The independent script currently reports eight failed assertions representing these five issue groups.
