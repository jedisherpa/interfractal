# Gate 10 model, interface and private service

Version `gate10-model-v1`. `fixture.json` is the complete public assessment input. The private key contains exact target results and explanations, and predictions contain the independent analytic oracle. Built-in Node/HTML/SVG suffices.

## Exact model and public information

Use reduced rational strings (`0`, `-3/2`, `25/16`) for exact data and comparisons. Normalize denominators positive and zero as `0`. For a 4D point q=(x,y,z,w), a known source turn followed by projection gives `(c*x-s*w,y,z)`. The query tokens have exact `(c,s)` pairs `a0=(1,0)`, `am=(3/5,4/5)`, `a90=(0,1)`, `a180=(-1,0)`. `am=atan2(4,3)` is strictly between 0° and 90°; its approximate degree label is descriptive only. Each observation applies directly to the original source. No incremental rotations or decimal trigonometry determine the exact outputs.

For a ball centered at `(0,0,0,cw)` with unknown radius R≥0, slice w=s has delta `R²-(s-cw)²`. Positive delta is a 3D ball with radius sqrt(delta), zero is one point, negative is empty. An empty result has `radiusSquared:null`, `radius:null` and retains the negative `delta`; never clamp it into a point. Nonempty supports provide exact radiusSquared. The two supplied supports determine each transfer case's cw and R² by subtracting their equations. Source parameters and solved target delta are not public before reveal. T03 has two admissible sources and no selected true source; its correct result is the full set of two target outputs.

Known formulas, query definitions, support raw values, candidate answer alternatives and T03's stated possible w values are public. They are hypotheses/information, not a correctness signal. All unrevealed UI/DOM/JSON/attributes show only this data. In particular, do not add a recovered source, target diagram, rank/identification badge, computed target delta, answer styling, selected “correct” option or explanation before deliberate reveal. A static search for the expected number alone is not a valid leakage test because response alternatives intentionally include it. Audit the privilege/meaning of each field.

Draw supplied supports as two equal-size cards, each SVG 280×200 CSS pixels, wrapping at narrow widths. Raw exact values and six-decimal labels accompany them. For drawing only, convert rationals to finite numbers. Use orthographic display yaw then pitch: `u=x*cos(yaw)+z*sin(yaw)`, `d=-x*sin(yaw)+z*cos(yaw)`, `v=y*cos(pitch)-d*sin(pitch)`; screen coordinates `(140+50*u,100-50*v)`. Default yaw0°, pitch20°; T03's second card alone has yaw45°. Display depth is discarded. Fixed 50 CSS px/unit, no autoscaling or jitter. Ball drawings use the same scale and show radius text; point and empty have distinct visible and accessible labels. Diagrams are ordinary 2D drawings of supplied 3D observations, not additional source measurements. There are no free source, target or camera sliders. T03's camera change preserves its raw xyz exactly.

The target panel initially contains only the named query, alternatives and the literal status `Target result withheld`. No placeholder geometry should imply the answer. After reveal, render only the returned exact target record and explanation. T03 displays both possible target points with the label `Two possible outputs; no unique prediction`. Source equations/derivations may be returned in the explanation after reveal, but private audit files are never served wholesale.

## Practice, local review and saved tour

The practice card always uses P00 only. Open/close are explicit controls; opening pauses a running tour and logs the actual deviation. Practice has a worked answer, no response controls, and no assessment receipt. Its visibility is part of the semantic state.

There are two display modes: `saved-tour` and `local-review`. The saved mode disables assessment response/reveal controls and labels itself `Scripted software demonstration — no predictions or reveals`. **Inspect this case**, a task selection, or practice opening pauses the tour and enters local-review. Its initial `responsePhase` is `none`; **Start software prediction** creates an attempt for the selected case. Option selection is an editable draft only while `answering`; **Commit answer** or **Skip answering** sends it to the service. Draft choices never count as committed responses. Pending requests disable conflicting case/reset/answer controls and visibly say `Awaiting server acknowledgement`; the app must not optimistically unlock reveal.

After a successful commit acknowledgement, `responsePhase=committed`, response controls lock and `Reveal result` becomes available. Reveal is another deliberate action and request; only its valid response sets `responsePhase=revealed`. A network failure retains `pending/unknown` status and permits idempotent retry, never a guessed success. A late response must be bound to its original session/attempt/case/build and cannot populate a different current view.

**New review attempt** creates another attempt even for the same case and shows its ordinal/priorReveal status. **Hide result / inspect another case** removes the visible result without revising the ledger; **Reopen saved start**, replay-from-start and checkpoint restoration clear all local draft/result/receipt UI and select pure canonical state. The same document's session and server records remain retained, with no old receipt automatically reattached to canonical state. Starting a new attempt automatically closes any prior open uncommitted attempt as abandoned; closing a committed/revealed view only detaches it. Ordinary reload loses the in-memory session capability and creates a new anonymous software session on later local use; old server records remain until expiry/process end and are exported by the host first. No localStorage, shared cookies or URL-carried receipts. New tabs cannot reveal another document's attempts.

The canonical tour lasts 20 seconds. It starts paused at0 on T01, practice closed, no draft/attempt/answer/reveal/session attached to canonical state. At4/8/12/16 select T02/T03/T04/T05, respectively. At20 select T01 then stop automatically, paused at cursor20 with reason exactly `end-of-sequence`. Every boundary task-select has `origin=replay`, provenance `scripted_demonstration`; the final stop has `origin=automatic` with the same scripted provenance. At0 there is an initial state, not a fabricated task-selection event. Both support cards remain static within each four-second block. No target output, answer selection, commit, practice or reveal occurs in the canonical events or checkpoints.

Checkpoints are 0,4,8,12,16,20. Apply all boundary events before taking a paused checkpoint. Pause caused by checkpoint restore is not a manual action hidden inside the replay. Global Play/Pause, Previous/Next checkpoint, direct checkpoint, Replay from start and Reopen saved start must work. Only the global tour has a clock. Every local exploration pauses it. A real uninterrupted UI-started run through20 supplies natural-stop evidence; jumps/manual steps do not.

## Strict service boundary

Bind to loopback 127.0.0.1 only. GET/HEAD allow exactly `/`, `/index.html`, `/app.mjs`, `/model.mjs`, `/style.css`, `/fixture.json`, `/build.json`, `/run/run.json`, `/run/initial-state.json`, `/run/events.jsonl`, `/run/checkpoints.json`. Equivalent implementation filenames must be enumerated in the immutable route manifest before candidate freeze. No directory listing, generic source/review tree, source maps, audit files, private files, arbitrary run IDs or filesystem access. Direct/encoded/double-encoded traversal and unknown routes fail. Private key and predictions are packaged in a nonserved private area for exact-build recovery; no browser import of private logic/data. Canonical files contain only public task state and scripted events.

`/build.json` is a sanitized public identity/route manifest, not a copy of the private build manifest. It must omit private key/prediction paths, content hashes and lengths as well as their contents. Public assets may identify the overall immutable build and public fixture without exposing private file metadata.

Review routes may later allow only host-approved, answer-free `/review/results.html`, `/review/replay-collection.json`, `/review/source-review.md`, and individually enumerated answer-free screenshot names. Answer-bearing local exports, logs, screenshots, packet details or audit files must not be made public through that surface. Results can describe mechanics and limitations without publishing the per-case key. The host can link full artifacts by local filesystem path; those local links do not authorize corresponding HTTP routes. Serving a new review artifact requires checking its actual contents and exact bytes; an intended allowlist alone is insufficient.

All API success/error responses use `Cache-Control: no-store`; disable cross-origin access, check mutation Origin is the exact local origin (allow documented nonbrowser same-origin audit requests), accept JSON only, limit request size and reject unknown fields/types. APIs accept only POST. There is no GET key, reveal, response ledger, session list or debug state. Static routes must never depend on the last session's answers or reveal status.

1. `POST /api/session` with `{actor:"software_validation"}` returns opaque unpredictable document-scoped `sessionToken`, public sessionId, buildId, expiry and `humanEligible:false`. No correctness/reveal data. The token stays in memory, not a cookie, URL, DOM inspector or ordinary export. Maximum64 sessions and32 attempts per session; capacity rejects explicitly. Sessions expire30 minutes after creation or at process end. All later operations reject an expired session; never silently convert it into a fresh one.
2. `POST /api/start` with `{sessionToken,buildId,caseId,requestId}` creates one immutable attempt identity and returns attemptId, caseId, ordinal, priorReveal, status `answering`, provenance and firstExposureHumanEligible:false. The server rejects practice/unknown case/build. Repeating the same requestId/payload returns the same attempt; conflicting reuse rejects. A new start closes any prior unanswered open attempt as abandoned without deleting it. Current committed/revealed attempts remain retained and detached.
3. `POST /api/commit` with `{sessionToken,buildId,caseId,attemptId,requestId,response:{kind,optionId}}`. `kind=answer` requires a valid option ID; `kind=skip` requires null. Validate and store the response before acknowledging. Bind it to this build/session/attempt/case; lock it immutably. Return only receipt, attemptId/caseId, committed response, locked:true, grading:`withheld`, server event reference and commit sequence/time. No correctness, key, target, explanation, expected hash or answer-specific message/HTTP status. Same request/payload retry returns the same receipt without a second accepted commit. Any different response or conflicting request reuse after lock returns409 and preserves the original. Receipts are unpredictable capabilities in addition to session binding; do not include them in normal inspector/evidence export.
4. `POST /api/reveal` with `{sessionToken,buildId,caseId,attemptId,receipt,requestId}` requires that exact valid committed receipt and session. Missing, guessed, precommit, cross-case, cross-build, cross-session and expired credentials reject with no private data. The server records the deliberate reveal acceptance before returning target, explanation, expectedOptionId and `softwareGrade` (`correct`/`incorrect` for answered, null for skip). Repeat reveal for the same receipt is idempotent content and marked repeated, never another answer. Distinct valid requests may log repeated reveal intent without changing the original first reveal. No automatic reveal or prefetch.
5. `POST /api/close` with `{sessionToken,buildId,attemptId,reason}` (`inspect-other-case`, `reopen-saved`, `new-review`, `hide-result`) detaches the view and abandons only uncommitted attempts. Committed responses and first reveal history never change. It returns no private payload. A reload need not synthesize a close; a lost open attempt remains incomplete until server expiry.
6. `POST /api/export` with `{sessionToken,buildId}` is a read operation returning this session's redacted ledger. Include actual responses and acknowledged commit/reveal event references, and target/explanation only for attempts that this session deliberately revealed. Unrevealed attempts remain ungraded. No session tokens/receipts, other sessions, private key, unrevealed expected option or computed scores. Export text is cleared when selecting canonical state; it must never shadow the selected replay with stale local data.

These APIs are necessary local mechanics tests, not a human study or cryptographic commitment protocol. Source/code owners can read the private files; public formulas allow deriving answers; screenshots and remembered explanations cannot be revoked. The tested promise is server-ordered UI/service disclosure, not secrecy from a privileged operator. Retain the append-only server action ledger outside immutable build/run directories with credentials redacted, and preserve it in local host evidence before expiry/shutdown. Do not claim durable participant storage.

## Atomic snapshots and fingerprints

Canonical JSON recursively sorts object keys, preserves array order and normalized rational strings, has no whitespace, and hashes UTF-8 with SHA-256 lowercase hex. A semantic payload contains mode, exact cursor, paused, caseId, practice visibility/content when open, supplied support/query/options, selected draft option, responsePhase, safe acknowledged response/reveal or null, and review status. It excludes timestamps, tokens, session/attempt/event IDs, viewport, counters identifying unrelated past attempts and export text. A pure canonical payload contains no local response/reveal even when its document previously revealed that case. Hash it as `semanticFingerprint`; checkpoints compare only these equivalent paused canonical payloads. A separate `ledgerFingerprint` covers the redacted actual ledger and review/exposure metadata; it is not expected to reset to a checkpoint hash.

For every published frame/inspector, advance the engine once at one captured clock value, clone the semantic payload and safe ledger, derive support/display data once, capture viewport/scene metadata once and assign a monotonically increasing snapshotRevision. Compute hashes solely from those immutable clones. Render and publish those same clones and their hashes together, discarding any older async result after a newer revision. Do not calculate a hash from a later live state or separately update inspector text. The DOM observation gives complete `semanticPayload`, `semanticFingerprint`, `ledgerPayload`, `ledgerFingerprint`, snapshotRevision and fresh viewport/scene dimensions. Evidence capture reads that published object once; it never synthesizes a payload from several clock reads. The auditor independently rehashes every captured semantic/ledger payload, not only self-reported comparisons.
