# Gate 12 model, records and replay

Version `gate12-model-v1`. Use exact safe integers and strings from the frozen public fixture. Runtime calculations must not import the independent-predictions oracle.

## Sources, references and procedure

Modes are P1=(channels2,minutes1), P2=(4,3), P3=(6,5). Fixed tie order is P1,P2,P3. The source is wholly synthetic. `R_DETAIL@1` orders decreasing retainedChannels, then fixed tie order; `R_SPEED@1` orders increasing sendMinutes, then fixed tie order. Rank is the zero-based position among **all three source modes**, independent of availability. Detail ranks P3,P2,P1; speed ranks P1,P2,P3. Ranking explains the chosen first mode; it is not a cardinal utility scale.

Groups are `ARCHIVE` and `DISPATCH`. Reference assignment `BASE` binds Archive→R_DETAIL, Dispatch→R_SPEED. Assignment `DETAIL_CONTROL` binds both groups to R_DETAIL but preserves their separate group identity and explicit reference/version. Assignment is locked when a new branch is created. Changing it requires a fresh branch; no earlier proposal is edited. The sources and procedure do not change.

Scenarios are `ALL` with eligibility[P1,P2,P3], `EXTREMES` with[P1,P3], and `NONE` with[]. They are stipulated availability sets, not actions by the groups. Changing scenario never changes a recorded local ranking. Unknown modes, scenarios, assignments, references, malformed proposal/source bindings or duplicate group records are invalid and rejected without model change.

`evaluateProcedure(proposalsByGroup, scenarioId, procedureId)` validates immutable proposal content against the declared source/reference definitions. Missing groups are checked first and produce `blocked-missing-proposal`, listing exactly what is absent. With both present but an empty eligible set, return `blocked-no-eligible-option`. In either blocked state `jointAction=null`, `selectedModeId=null`, and match-to-proposal values are null, not false.

Otherwise each eligible mode p gets `ranksByGroup` and `worstRank=max(rankArchive(p),rankDispatch(p))`. Find the minimum worstRank, list all tied minimizers in fixed order, select the first and record whether tie-breaking was used. No rank sum, hidden weighting, averaging of references or deletion of objections is permitted. The selected record has `status:procedure-selected`, `jointAction:{operation:simulate-shared-export,modeId,slotCount:1,enacted:false}` and a complete derivation table. Its status describes the stipulated rule only.

With both proposals present, include `firstChoicesByGroup`, `differentFirstChoices` and, when selected, `matchesFirstChoiceByGroup`. These are descriptive comparisons, never an acceptance vote. Preserve the complete original proposal contents and hashes. In BASE, first-choice disagreement remains true after P2 or P1 selection and after a blocked NONE outcome. In DETAIL_CONTROL it is false because both functions prefer P3; still label `No human endorsement inferred`. With missing proposals, comparison is incomplete and differentFirstChoices is null. Do not fill missing judgments with defaults.

## Immutable local proposals and outcome records

The initial saved view is read-only scripted state. **New local branch** creates an empty local branch with the selected next-branch assignment and ALL scenario. No network/session/start acknowledgement is needed. **Record Archive proposal** and **Record Dispatch proposal** derive the selected group's full judgment from its bound reference, not from the joint outcome or another group's view. There is no free-form fabricated human answer. A second record for the same group rejects as `proposal-already-recorded`; the existing content remains unchanged.

Proposal semantic content is `{groupId,reference:{id,version,question,ordering,scope},sourceHash,ranking:[{modeId,rank,referencedValue,sourcePath}],preferredModeId,derivation,provenance:source_informed_software|scripted_demonstration}`. Actual record ID, branch ID, document UUID, creation time and origin event reference are held in a provenance envelope. Hash the content separately; creation order does not change ranks/choice. Group identity remains in content even when both use the same reference. The source hash identifies canonical JSON of the exact ordered source modes.

**Evaluate joint procedure** is available even with missing proposals. It creates an immutable outcome record containing assignment, scenario/eligibility, exact proposal content hashes, procedure/version, status, derivation rows/ties/selection, preserved local comparison and jointAction or null. Missing-proposal results cite only actually present records. Its envelope links the originating real control/scripted event and exact proposal record IDs. Outcome IDs and times are not authority or consent.

Within a branch, repeating an evaluation with the identical scenario and proposal content reselects the existing record, logging `reusedRecordId` without manufacturing a second action. A new proposal or scenario changes context and may create a new outcome. Existing outcomes are never revised. Scenario selection clears the current outcome display until evaluated; it retains history. A separately labeled **Inspect retained outcome** view shows its recorded context and must not present a historical result as an evaluation of the current scenario. Selecting a prior branch likewise cannot rewrite its assignment, proposals or outcomes. Keep at least the two prescribed local branches and all their records exportable before reload.

Canonical records live in a separate immutable registry. User actions never append into the scripted branch or pretend to have performed its proposal/action events. Opening an ordinary local branch always starts empty; it does not adopt canonical proposals as local creations. Checkpoint/reopen/replay selects only canonical records and clears visible local export/record-inspection text. Existing local branches remain in the document registry until reload; reload clears them and must disclose that behavior. The per-document UUID is outside semantic/information payloads and content hashes, and changes on reload. Event envelopes use it to distinguish separate actual documents.

## Display and information parity

Show both group cards simultaneously with their explicit local question, source-ranked alternatives, recorded/unrecorded status and first choice. Source facts and declared procedure remain inspectable. A distinct joint panel reports blocked/selected status, eligibility, rank table, tied set and tie-break. Below a selected action, retain both local recommendations and match indicators; do not replace them with a shared yes/agreement badge. Display `Different local recommendations retained` when applicable, and `Same modeled first choice; no human endorsement inferred` for the control.

Both `diagram` and `plain` use the same semantic object and all controls. The diagram lists typed `judged-under`, `derived-from`, `input-to` and `selected-by` relations; the plain table lists identical source/target/type triples. It adds no arrows implying consensus, consent, influence or physical communication. Both representations expose full proposal/action records, reasons and provenance through the same inspection controls. No representation receives extra inputs. A raw record inspector is evidence of supplied records, not a human understanding measure.

Minimum controls: next-branch assignment, New local branch, branch selection, two Record proposal buttons, scenario, Evaluate joint procedure, Diagram/Plain, Inspect retained outcome, source/reference/record inspector, Export local record, and replay controls. Disabled actions may be honest non-actions in browser evidence; model rejection tests cover unreachable invalid inputs. No server mutation endpoints are needed.

At20 select EXTREMES then evaluate it, selecting P1 by the fixed tie-break. At24 restore the initial canonical display/empty selection while retaining cursor24, then stop automatically. The registry retains the immutable canonical proposal/outcome records even when the displayed initial state is restored.

There are eight scheduled events: one each at4/8/12/16, two at20 and two at24. All scheduled mutations have `origin:replay` and `scripted_demonstration`; the final stop has `origin:automatic`, same scripted provenance, reason exactly `end-of-sequence`. At0 there is an initial state, not a fabricated interaction. Checkpoints0,4,8,12,16,20,24 apply all boundary events and then pause. Only the global tour owns a clock. Starting local work pauses it. Play/Pause, Previous/Next, direct checkpoint, Replay from start and Reopen saved start are available. A local record is never retroactively turned into a canonical event. On resumed checkpoint playback, subsequent scripted records refer to canonical provenance, not new local authorship.

## Snapshot, export and HTTP contracts

Canonical JSON sorts object keys recursively, preserves array order and safe integers/strings, uses no whitespace; SHA-256 hashes UTF-8. Content hashes cover sources, references, proposals and outcome content. `informationPayload` includes all selected source/reference/record/procedure facts and inspectable history currently displayed; it excludes representation, clocks and transport metadata. Equivalent diagram/plain states must have equal `informationHash`. `semanticPayload` additionally includes mode, representation, cursor/paused/end state, active assignment/scenario, selected branch's semantic records and inspection selections. Exclude document UUID, wall time, event-envelope IDs, viewport, export text and unrelated historical branch content. Include complete payloads beside their hashes. A separate export history preserves every immutable local artifact with its actual provenance envelope.

Advance the engine once at one captured clock value, clone semantic state, derive once and render/hash only that clone. Use a semantic-generation token independent of snapshotRevision. A metadata refresh may not invalidate a newer pending semantic publication or republish an older state. Queue layout measurement until semantic rendering completes; discard obsolete semantic hash results. Measure viewport/document/scene after export/inspector rendering, resize and scroll, then publish matching metadata without altering semantic content. Test the paused control→scroll race explicitly. Capped exports/inspectors may scroll internally; report that limitation.

Export first records its own export event, then serializes a truthful included-through sequence, current context, all local branches/proposals/outcomes, source/reference hashes and origin references. It does not recursively include its own serialized bytes. Later controls are outside that prefix and remain in host evidence. Canonical restores clear visible export text. There is no hidden study storage; the host preserves exports before reload.

Do not return deep nested tool objects or numeric cursor previews as the sole hash evidence. Retain tool-limit failures and retry only the read when an action already succeeded.
