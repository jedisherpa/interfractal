# Gate 13 model and publication contract

Version `gate13-model-v1`. `fixture.json` is the finite source of names, values, authored statements, scale policies, corrected text and tour. Author expectations in `independent-predictions.json` require independent review; no implementation exists at specification time.

## Exact derivation and valid states

For each case let integer counts be `a,b`, original lower bound `l`, upper bound `u=100`, and plot width `w=240` SVG units. Preserve order A,B. Compute difference `b-a`; statement truth `b == 2*a`; offsets `(a-l,b-l)`; and widths `w*(a-l)/(u-l)`, `w*(b-l)/(u-l)`. Count ratio is reduced `b/a` when `a != 0`, otherwise `{status:"undefined",reason:"zero-denominator"}`. Bar-length ratio uses `(b-l)/(a-l)` with the same zero-denominator rule. Use reduced rational numerator/denominator records and exact safe-integer comparisons, not rounded decimals or JavaScript Infinity/NaN. All selected widths happen to be integers.

MISMATCH original widths are 80/160; corrected widths 192/216. TRUE_CONTROL widths are 96/192. ZERO_CONTROL widths are 0/24 both before and after correction. Corrected lower bounds are zero; the source counts and upper bound remain unchanged. Zero-length A stays visible as a labeled zero marker, with no positive-width bar invented for emphasis. SVG viewBox width is 320 with a 240-unit plotting region; responsive scaling may change screen pixels but not viewBox widths or their ratios. Display numerical labels and baseline ticks; avoid 3D perspective, area encoding, animation of data values and clipped labels. Axis lower bound is inspectable in the main view, not hidden in a tooltip.

Original statement predicate is always `TWICE_COUNT@1`, and **Check original statement** always checks that predicate, including when the correction is displayed. Label its result **Original statement: false/true** so “false” cannot be mistaken for the corrected summary's status. Correction facts are independently checkable: original/source IDs and hashes; exact difference and count ratio; unchanged source counts; old/new scale; corrected text; diagnosis; and record-creation provenance. Corrected summaries are true for their sources. There is no corrected version of TRUE_CONTROL: it is already accurate. The valid display combinations are `(MISMATCH original/corrected, TRUE_CONTROL original, ZERO_CONTROL original/corrected) × (visual/plain)` = ten. Unknown case/version, corrected TRUE_CONTROL, malformed counts/axis, mismatched source/display/check binding and correction without a matching false check reject without state mutation.

## UI state and immutable history

Use a single local review map keyed by the three case IDs, not a branch/session system. **Start local review** enters an existing or empty review of the selected case. **Case** changes the local case without modifying any stored record; it opens that case's newest valid version. **Representation** changes visual/plain only. **Inspect source evidence**, **Check original statement**, **Apply correction and debrief**, **Show original**, **Show correction and debrief**, **Inspect records** and **Export review record** work identically in both representations. Case selection in saved-tour mode enters local review; canonical playback cannot create local records.

Each local case has one immutable check per exact original/source binding, and zero or one correction. A repeated check reuses the record and logs `reused`; it does not manufacture a second judgment. Applying correction is enabled only after a false check and before that correction exists. Before checking, after a true check, or after correction, the disabled control is a non-action; model rejection/reuse tests must not be reported as actual button clicks. Showing the original after correction retains the false-check status and an explicit **Correction available; original retained for inspection** marker. Showing the correction reopens its full debrief; nothing silently discards the earlier error.

Check content: case ID, source ID/hash, original display ID/hash, statement ID/version/text, predicate/equality operands, truth verdict, difference, exact count ratio, exact original offsets/widths and length ratio, diagnosis, and provenance class. Correction content: case/source/original hashes, referenced check-content hash, corrected display ID/hash/text, old/new lower bound and exact widths, true correction facts, debrief and provenance class. Stable SHA-256 content hashes exclude record ID, UUID, wall time and event sequence; those belong in record envelopes. Local envelopes identify `host_controlled_software`; canonical envelopes identify `scripted_demonstration`. Neither is a human response or assent. Source, original display and prior records remain byte-equal after representation/case changes, original/correction inspection, export and saved restore.

The public canonical records may be precomputed. They must have explicit scripted provenance. At saved cursor zero the active semantic/display mask has no performed check or correction; public registry presence is not evidence an action occurred. Export separates local records from canonical script definitions and actual playback events. No secrecy or temporal withholding claim is made.

## Same-information representation and checking access

Both representations show the same authored statement, warning, source/count labels, axis bounds, plot-width definition, scale offsets and provenance affordances. The plain table lists A/B count, lower/upper bound, offset and bar width; the visual view labels the bars and includes the same encoding table or readable numeric key. The source panel contains identical complete fixture rows and source IDs, reachable with the same enabled control before any check. The checker and correction use the same functions irrespective of representation. All debrief text, record history, source links and actions remain available in both. A graphic may reorganize these facts but cannot add a checking hint or exclusive fact. Equal evidence access does not establish equal human effort or skill.

The information payload includes active case/version, source/display definitions, visible check/correction content, warning/debrief, numeric encoding, local history index and available substantive operations; exclude representation styling, cursor, transport metadata and UUID. Equivalent visual/plain states must have equal information hashes. Semantic payload additionally includes mode, representation, paused/cursor, active source/record-inspection state and selected version; exclude wall time, UUID, viewport, export text and unrelated transport counters. Do not include record-envelope IDs in semantic comparisons. Export/metadata refresh must not change those fingerprints unless substantive state actually changes.

## Deterministic replay and publication

Saved duration 24 seconds; checkpoints 0,4,8,12,16,20,24. Initial state is paused MISMATCH/original/visual, source closed, no active check/correction. Scheduled events: 4 source-open; 8 original-statement-check false; 12 correction-apply and debrief; 16 representation plain; 20 show-original with correction marker retained; 24 canonical-restore opening display while retaining cursor24, then automatic tour-stop `end-of-sequence`. This is seven ordered scheduled events. Canonical restore masks active records without deleting the public script definitions. Manual checkpoint24 is not a natural stop.

Use one global replay clock and one captured finite cursor per publication; local actions pause it. Clone semantic state once, derive/hash/render that clone, and publish consistent inspector data. Keep semantic generation separate from layout/metadata revision. Scroll, resize, expanded exports and inspector toggles remeasure the resulting viewport/document/scene without invalidating a pending latest semantic publication. Reject obsolete async hashes; do not reject a legitimate semantic result solely because layout metadata refreshed. Verify delayed-hash races programmatically and immediate real DOM layout after export/scroll/resize. Arrays have fixed order; canonical JSON has sorted object keys, finite numbers and explicit nulls.

Events contain sequence, UTC, run/build/document UUID, captured cursor, type/payload/result, actor/provenance, origin (`user-control`,`replay`,`automatic`) and before/after semantic hashes. Origin denotes control source, not a human participant. Each export appends its own event before serialization, includes `includedThroughSequence`, then serializes complete local records and event prefix without recursive export bytes. Reload starts a new UUID and empty local history. Reopen/checkpoint controls preserve the current document's local history while displaying only canonical state.

## Runtime boundary

Use `misleading-view/`, immutable builds `g13-<source-hash-prefix>`, runs `G13-MISLEAD-001` through `003`, Node24 and loopback44006. Immutable server requires explicit absolute `--run`; missing run, mismatched run/build or manifest hash fails. Pin executable/version, source manifest, build, fixture, oracle, events, checkpoints and run. Serve only explicit GET/HEAD routes for `/`, application modules/style, `/fixture.json`, `/build.json`, and exact canonical run assets. All contents are public. Reject path traversal, arbitrary files, unknown routes and mutation methods. Do not expose the repository by a generic static server. A later `/review/` allowlist is separate from the immutable tested app and is audited after synthesis. Link the preserved Gate12 replay/results and retain exact previous restart identities.
