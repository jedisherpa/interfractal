# Gate 7 model, presentation and service contract

Version `gate7-model-v1`. The data contract is `task-fixture.json`; private answers and expectations are independent audit inputs. Use built-in Node and HTML/SVG with no new package dependency.

## Public data and calculations

`fixture.tasks` contains eight neutral IDs, prompts, available facts, option IDs/labels and frames. Do not encode scoring in filenames, ID names, option classes, label colors or ordering conventions. Point markers identify stable within-case correspondences: the first point uses a circle and a second point uses a square where present. Use restrained consistent colors unrelated to answers. A selected point is not a marked “correct” option.

Point frames contain only allowed observations: `parameters.alphaDegrees`, optional `betaDegrees`, `points[].xyz`, marker/ID and `displayCamera`. The raw coordinate table is part of all three conditions, displayed to six decimal places with full-precision raw projected observations retained in the public fixture. Numeric recovery is conditional on these **raw 3D observations, known rotations and correct correspondence**; it is not a theorem about the two-dimensional SVG image. No rank, inversion result, recovered source coordinate or source coordinate inspector appears before reveal.

The public formulas are column-vector rotations: x′=x cosα−w sinα; y′=y cosβ−v sinβ; z′=z. Apply x–w then y–v; these planes are disjoint in this fixture. A 4D observation omits β and preserves y. For drawing only, use one explicit ordinary orthographic camera convention consistently, e.g. yaw then pitch and drop display depth. The fixture's fixed scale is105 CSS units per coordinate; the final renderer must declare its exact camera convention and retain raw observations when the display camera changes. No perspective adjustment or per-frame autoscaling.

Ball comparison frames provide observed projection and slice kinds/radii. Render `kind: empty` as an explicit empty-state panel, `kind: point` as one marked point (with a text alternative), and `kind: ball` as an ordinary 3D-ball drawing. A zero radius must not stand for both point and empty. Q05 supplies observations at s=0.3,0.9,1.5 and asks for an unshown s=1.8 prediction; do not add that setting to task-facing frames before reveal. Its declared source has center(0,0,0,0.3), radius1.2 and slice w=s: radius²=1.2²−(s−0.3)². Use tolerance1e−10 for analytic boundary arithmetic. Q06 supplies a radius and camera changes; no hidden signed s/t values may appear in UI, dataset, attributes, inspector or task API. Candidate option labels are hypotheses, not supplied actual settings.

Q07 summaries contain capacity60 headlines but no cost data. Do not infer missing values from Q08, history, key or defaults. Q08 records provide capacities, existingAccess and requiredCosts. The receiver numeric screen uses capacity≥capacityMin and sum(requiredCosts.tokens)≤budgetMax. Alternative existing-access reference is not an extra receiver condition. Source record bytes/history and local reference identity remain unchanged through reference/receiver frame switches. Graph and plain modes receive the identical frame object; graph edges, if drawn, are typed required-cost dependencies and imply no extra relation. Neither mode displays the requested calculated pass/fail answer until reveal. The inspector may show only the public supplied data.

## Finite-view conditions

Geometry permits `static`, `prescribed`, `interactive`; attention permits `attention`, `plain`. Reject invalid task/condition pairs, choosing the task's declared default when switching families. Static shows all three frames. Prescribed plays F1 at0≤t<2, F2 at2≤t<4, F3 at4≤t≤6, stopping paused at6 with `end-of-sequence`. Pause, restart and manual stepping do not add frames. Interactive uses explicit F1/F2/F3 buttons without interpolation or extra controls. Q07 has only F1. Attention Q08 can choose its three supplied frames in either layout. Changing representation preserves task/frame and the underlying data. It must not select or score an answer.

Checkpoints are0,6,12,18,24,30,36,42,48. Nine checkpoint semantic hashes must repeat after exploration, Reopen saved and reload. Playback wall time does not define the authoritative simulation cursor.

## Suggested minimal exports

`model.mjs` may export `initialState()`, `stateAt(seconds)`, `deriveView(state)`, `transition(state,event)`, `fingerprint(state)` and constants for duration/checkpoints. Equivalent clear names are acceptable if documented by the builder. `stateAt` and `deriveView` are deterministic over the frozen public fixture. `fingerprint` excludes wall timestamps, browser sessions, receipt tokens and viewport; it includes task, condition, frame(s), supplied semantic data and display camera. The saved-state/checkpoint fingerprint also includes the simulation cursor/mode/paused state as declared by the builder, so compare equivalent paused checkpoints, not active states. Provide a separate public information fingerprint for cross-condition equality that excludes layout/access mode.

## Private service and answer isolation

Copy only public fixture/model/app/style/index/build metadata and declared saved-run assets to served routes. Hold `private-answer-key.json` in a separate nonserved build area for exact-build recovery. Never import it, predictions or computed scoring into a browser module. No directory listing, wildcard source serving, arbitrary file-read route or generic review-tree exposure. Check traversal and encoded traversal as well as direct key filenames. Public evidence pages must not embed exact task answers before an intentional spoiler action. Local filesystem audit links can remain separate from the task service.

POST `/api/submit` takes `{taskId, choiceId, skipped, actor}` where skipped requires null choice; actor is `software_validation` or `unattributed_local`, never inferred human. It returns `{receipt,taskId,locked:true,skipped}` and no correctness, explanation or source data. The server validates options and stores a bounded in-memory receipt record; tokens are opaque and unguessable. Client answers are transient; no enrollment or identity collection occurs.

POST `/api/reveal` requires the valid receipt and matching taskId, representing the separate intentional reveal action. Only then return `{taskId,choiceId,explanation}` from the held answer entry, optionally score the submitted non-null choice as **local/software check only**. Keep `privateDerivation` out of the response. GET reveal and unauthenticated/mismatched receipt requests fail. A user may submit a skip, then reveal, without inventing an answer. Hide or disable the reveal button until a submitted/skipped receipt exists. No prefetched/cached explanation before intent. Session reset clears client receipt/reveal state; prior stale server receipts must never be reused by fresh state. Response exports never enter the canonical replay.

The allowlist may serve closed Gate7 evidence after the host checks that it contains no unrevealed answer explanations. Prior replay links use their historical ports/builds. Browser test helpers/`window` observation objects may expose public state and response mechanics only; no key or private derivations even in software-validation mode before reveal.
