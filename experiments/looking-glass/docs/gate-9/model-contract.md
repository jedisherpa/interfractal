# Gate 9 model, trace and mode contract

Version `gate9-model-v1`. The new fixture contains exact copies of the four Gate 8 C02 worlds, with one fixed public reference C02-W02. It also contains an independent worked practice card and four audit recipes. Recipes are choice-input descriptions, never independent watch or static payloads.

## Exact records and compatibility

Rationals are reduced `n` or `n/d` strings, positive denominator, zero `0`. Equality uses exact canonical rationals, never rounded labels or a tolerance. For source `(x,y,z,w,v)`, original-source queries are `project=(x,y,z)`, `xw90=(-w,y,z)`, `yv90=(x,-v,z)`. Observation shape is `{kind:"point",pointId:"P",xyz:[...]}`. These are known raw 3D records with known point correspondence, not recovered arbitrary screenshots. Display arithmetic may use floats; numeric drawing tolerance is1e-10.

The chosen reference has source `(1/2,-1/2,0,-1,+1)`. Its three possible outputs are `(1/2,-1/2,0)`, `(1,-1/2,0)`, `(1/2,-1,0)`. Compare a candidate with the reference only on selected query IDs and their exact outputs. Retaining only project leaves all four worlds; adding xw leaves W01/W02; adding yv leaves W02/W04; both leave W02. The property is determined iff all compatible candidates have the same sign pair. Repetition creates another occurrence without narrowing that set. In this family all property pairs differ, so determined is equivalent to a singleton compatibility set.

## Trace is the common data source

Initialize a draft with occurrence 0=`project`. An accepted `choose-query` appends one occurrence with contiguous index 1 or2, its queryId and the exact output computed from the fixed reference. Repeats append rather than become no-ops. Reject malformed/off-menu choices and choices after index 2 without changing the draft. The second accepted choice is followed by an automatic `trace-seal` event; it freezes precisely those three occurrences. No value can be looked up under a different reference or inferred from an independent playback recipe.

The deterministic trace payload is `{schema,fixtureId,caseId,referenceWorldId,contextHash,occurrences}`; each occurrence is `{index,queryId,observation}`. `schema` is `gate9-choice-trace-v1`. A `traceHash` is SHA-256 of canonical JSON of this payload. Timestamps, session IDs, actor, draft ID and event IDs belong in a separate provenance envelope and do not change this content hash. Preserve the accepted choice-event references in the envelope and verify that their order/output exactly regenerates the payload. A canonical saved trace has `scripted_demonstration` provenance and the two frozen recipe inputs; it is never labeled a live or human choice. A local control-generated trace has actual event provenance, externally classified as software validation when applicable.

The same `deriveTrace` operation consumes the accepted choice sequence for canonical, audit and actual UI traces. `deriveWatch(trace)` returns the occurrence array unchanged in count/order/data plus the 2-second schedule. `deriveStatic(trace)` returns those same three occurrence objects for simultaneous display. It must not deduplicate static cards, regenerate missing queries, sort by fixture order, or invoke a different recipe. Both routes record the parent traceHash. The trace registry retains sealed entries; a new draft cannot overwrite them. Transient local traces need not survive reload, but must be fully exportable and preserved in the host evidence before reload. Canonical saved-run bytes do survive and must not be rewritten.

## Modes and observable access

`condition` is `choose`, `watch`, or `static`; `phase` is `draft`, `ready`, `running`, or `complete` as applicable. Choose begins in draft with the baseline visible, presents three clearly named query buttons, and shows the current occurrence only. The history roster retains ordinal/query labels; it does not expose unchosen query outputs. After sealing it is complete with the last occurrence visible. The public common source table is intentionally still available in every mode.

Watch/static controls are disabled without a sealed trace. Switching to either selects an existing sealed trace and enters ready, paused at local 0. Watch initially shows occurrence 0; static initially shows all three cards. Switching conditions does not alter the trace. Reopening choose on a sealed trace displays its complete last-occurrence state; **New choice** is the distinct action that begins a fresh draft. Query controls are disabled outside an unfinished choose draft. Show trace identity, condition, phase, selection count, local cursor and acquired-information status clearly. Do not call a loaded sealed trace a new choice.

Watch's forward local cursor ranges 0–6 and renders index `min(2,floor(localSeconds/2))`. On first rendering an occurrence, include it in `acquiredOccurrenceIndices`; previously acquired occurrences remain acquired during manual backtracking. A fresh watch/restart resets that list to[0]. `Next observation` visits0→2→4→6, rendering indices 0→1→2→2, then completes at 6. `Previous observation` moves to the prior such boundary without deleting acquired history. Completion requires all indices 0,1,2 actually visited in this route; no arbitrary forward jump or completion flag may fabricate exposure. A standard continuous watch visits all three. Manual stepping can complete a route but remains marked manual-review.

Static acquires all indices immediately at local 0, but readiness comparison is eligible only when its review clock completes at 6. Paused static remains visibly complete as a sheet; use a distinct phase so complete information is not confused with a completed timed route. **Finish sheet review** may move to6 as a logged manual-review action for accessibility. Pause/resume/restart and natural-stop semantics are explicit. Only one clock owner may run: saved tour or a local watch/static presentation. Manual exploration pauses the tour; starting the tour cancels local playback. Do not allow competing timers to emit duplicate transitions.

Computed compatibility and property-status summaries appear only for the completed route, so a future-frame result cannot leak through a running watch's status panel. The raw inspector for an unfinished watch contains only currently displayed/acquired outputs plus public common context and trace identity, not the sealed future occurrence payload. The app may hold the sealed trace in memory to render later; this is a transparent software instrument, not adversarial test secrecy. Full trace export and comparison summaries are available at complete endpoints. An in-progress trace inspector can list occurrence query IDs only when already acquired. All condition controls remain visibly labeled review actions, without answer/score widgets.

Use one identical observation-card component. Fix camera yaw 0, pitch 20°, scale 80 CSS px per coordinate; declare the precise yaw/pitch projection convention in README. No source turns between discrete observations, interpolation, camera controls or autoscaling. Each card shows exact rational xyz and two-decimal labels with negative zero normalized, and an ordinary point diagram. Use equal card drawing dimensions in all modes, e.g. 280×200 CSS px, responsive wrapping instead of shrinking on static. Static scrolling/layout differences are disclosed; information equality never asserts simultaneous on-screen visibility at every viewport. Every mode has the same common context and practice content.

## Fingerprints

Canonical JSON recursively sorts object keys, preserves array order, uses normalized rational strings and no whitespace. SHA-256 inputs use UTF-8. Document the canonicalizer; fingerprints are lowercase hex.

- `contextHash`: canonical JSON of the fixture's entire `commonContext` object (caseId, complete ordered worlds, reference, property definition, ordered query definitions/formulas, task text, instruction/practice content, fixed rendering constants). Same context in all modes.
- `traceHash`: deterministic trace payload above. It preserves order and repetition; T01 and T02 differ.
- `informationHash`: `{contextHash,observations}` where observations are unique `{queryId,observation}` entries sorted by fixture query order. It ignores occurrence multiplicity, condition, timing and trace identity. T01 and T02 agree; T03/T04 differ from them and each other.
- `acquiredInformationHash`: the same schema/operation restricted to occurrences actually acquired in the current route. At complete endpoints it equals that trace's informationHash. At static local 0 it already equals it; incomplete watch generally does not.
- `semanticFingerprint`: complete meaningful state including mode (`saved-tour`/`exploration`), condition, phase, paused flags, tour/local cursors, choices, acquired indices, trace payload/hash or null, current visible occurrence indices, completed summary, review/deviation status and practice visibility. Exclude timestamps, session/event/draft IDs, export registry history, viewport and mutable evidence metadata. Include exact payload, not only its displayed hash. Compare equivalent paused checkpoint states.

## Saved 24-second tour

The canonical tour uses recipe T01 only. It opens paused at 0 in choose with baseline and shared practice closed. At2 emit replay `choose-query:xw90`. At4 emit replay `choose-query:yv90`, then automatic `trace-seal` with reason `choice-budget-complete`. At6 emit replay `condition-select:watch`, then replay `presentation-play`; watch occurrence 0 is visible. At8 emit replay `observation-presented:index 1`. At10 emit replay `observation-presented:index 2`. At12 emit automatic `presentation-stop`, reason `end-of-presentation`, local 6, watch complete/paused. At14 emit replay `condition-select:static`, then replay `presentation-play`; all three occurrence cards are visible. At20 emit automatic `presentation-stop`, reason `end-of-presentation`, local 6, static complete/paused. At24 emit automatic `tour-stop`, reason `end-of-sequence`, tour cursor 24 paused. No answer, score, human actor, practice opening or non-T01 choice occurs in the canonical tour.

Checkpoint times are 0,2,4,6,8,10,12,14,20,24. A paused checkpoint applies all boundary events, then pauses both clocks; pausing for checkpoint restoration is not itself a manual-review deviation. Its phase can remain running at 6/8/10/14 with paused clocks. On resumed tour play, scheduled progress follows the canonical timeline. Continuous playback through boundaries must emit every specified event in order, including separate same-time events, before checkpoint state is sampled. At0 initialization is an initial-state record, not a fabricated interaction. Reopen saved start, replay from start and reload restore the canonical initial state; exploration never merges into it. Global play/pause, previous/next and direct checkpoint restore are available and logged.
