# Gate 9 replay, event and evidence contract

Version `gate9-record-v1`. All checks described here are prespecified and pending until actually performed.

## Immutable identities and events

Use `matched-observation/`, runs `G9-MATCHED-001` through at most003, content-addressed builds `g9-<source-hash-prefix>`, provisionally loopback 44002 after availability check. Each run records exact source/served-file hashes, base revision, Node executable/version, frozen prespec hashes and fixture identity. Retain immutable `run.json`, `initial-state.json`, canonical `events.jsonl`, checkpoints, canonical choice-event inputs and derived trace, and computation results. An existing content-addressed directory must be verified, never overwritten. No dependency installation or public deployment is needed.

Every semantic event has increasing sequence, UTC time, session/run/build, tour/local cursor, origin (`user-control`, `replay`, `automatic`), actor/provenance, type, intended payload, accepted/rejected result and before/after semantic fingerprints. User-control describes UI origin, not human identity; local actor defaults to `unattributed_local`. Host action evidence identifies software validation; canonical events identify scripted demonstration. There is no human score or gate-approval event.

Required types cover new-choice/abandon-draft, choose-query, trace-seal, trace-select, condition-select, presentation-play/pause/restart/step, observation-presented, presentation-stop, finish-sheet-review, practice-open/close, trace-export, tour-play/pause/replay/checkpoint/reopen and tour-stop. Equivalent type names may be documented before build freeze, but natural reasons below are exact. Repeated project/xw/yv selection is accepted while the choice budget remains; it is a new occurrence with unchanged unique information when redundant. Off-menu, malformed and over-budget selection is explicitly rejected and state-preserving, not silently replaced.

An accepted second choose-query produces two events: the originating choice append, then automatic trace-seal with reason `choice-budget-complete`. The first event leaves three occurrences in an unsealed draft; the seal freezes them and sets choose complete. Same-boundary events chain fingerprints and sequence, even when timestamps are equal. Do not collapse them. A choice displays its occurrence as part of choose-query, not an extra fabricated user observation event.

Selecting watch or static itself acquires/displays baseline or all cards, respectively, with the condition-select event containing the acquired indices. It does not emit a duplicate observation-presented event for that same display. During continuous watch, each later occurrence emits one observation-presented, with origin automatic for standalone playback or replay for the saved tour. Manual next/previous emits presentation-step and includes the displayed/acquired indices in that event, without a duplicate observation-presented. Natural local stop is automatic presentation-stop, reason `end-of-presentation`, local 6. Manual last-step or finish-sheet-review completes as its actual user-control event, reason `manual-review-complete`, never a natural stop. Pause while visible affects access and marks manual-review; checkpoint restoration is separately identified and does not.

The saved tour has exactly the scheduled model events listed in the model contract, apart from actual play/pause/replay/restore actions. At4 choose-query precedes automatic trace-seal; at 6/14 condition-select precedes presentation-play. Natural tour stop is automatic, reason exactly `end-of-sequence`, tour cursor 24 paused. Each boundary's after-state uses exact simulation time; live before-state may retain the latest actual fractional cursor. Do not misclassify that legitimate clock movement as a fingerprint-chain failure between different boundaries. Same-boundary chains must match exactly.

Browser-observable JSON includes complete state, visible/acquired query records, all fingerprints, current context, trace parent/provenance, phase/condition, counters, clocks, review status and fresh viewport/scene metadata. Hide future trace outputs in unfinished watch's UI/inspector as contracted. At endpoints export complete sealed payload plus event-reference envelope and the current completed-route summary. The host joins the three actually completed route summaries by traceHash; do not fabricate executions of the other modes. Export is a read operation, not a response or participation record. The host preserves actual local traces before reload. Browser observation JSON must be complete, not truncated console previews.
