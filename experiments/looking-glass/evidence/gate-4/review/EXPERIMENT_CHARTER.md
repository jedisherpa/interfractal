## Question and bounded claims

What does a known slice add to a projection, and what remains uncertain after a movie or additional control? The primary source is the analytically defined unit 4D ball B_0; its slice varies with the known plane w=s while its full 3D projection stays the same unit ball. A separate two-member candidate class `{B_+0.5,B_-0.5}` has identical initial slice and projection but distinct slices after known s=+.5. A separate rotated B_+0.5 projection movie has an explicit stored 3D numerical reproduction, demonstrating that movie appearance alone cannot establish a higher-dimensional origin.

Keep mathematical fidelity, bounded candidate distinction and human understanding separate. No participant performance is collected or invented. An agent inspecting source coordinates/answer keys is testing the instrument, not passing a visual comprehension test. A known intervention can reject this fixed recording without rejecting all possible adaptive 3D models.

Competing explanations/failures include displaying a projection as a slice, changing the source radius with the slice control, drawing an empty set as a point, hiding near-boundary values through rounding, coupling camera/source/clock, reusing analytic source calculations while calling them a stored 3D trace, incorrectly claiming a failed held-out recording proves 4D origin, or passing numerical tests with unreadable/incorrect interface geometry.

## Frozen conditions

All source definitions, equations, strict slice classification and expected numeric data are in `model-contract.md` and `independent-predictions.json`. The run opens paused at 0. One 40-second sequence uses 100 ms model samples with seven checkpoints 0/8/16/20/24/32/40 s. The primary unrotated ball has s=0→1.25→0, passing through center, interior, point and empty states. The clearly separate movie card rotates the shifted source 0°→90°→0° on the shared clock; labels must distinguish this rotation from the primary slice scan. The unrotated full projection reference stays fixed.

Every scene uses yaw 30°/pitch 20°, viewBox 640×420, scale 80, center 320/210. No autofit, automatic ordinary-camera motion, decorative jitter or canonical trails. Use non-color labels for solid/point/empty and candidate IDs. The initial ambiguity plane is 0; the stored 3D reader starts at frame 0. A checkpoint restores these defaults and all source/camera/display overrides.

Target comparison viewport is 1280×720 CSS pixels; actual measured values are authoritative. Additional supported resize checks use 1280×900 and 960×720. Use equal actual scene framing/camera/scale for primary center/point/empty comparison captures; differing viewports are separate declared conditions. Keep metadata current after scroll/resize/toggles. Report vertical navigation burden, clipping or unclear labels; do not infer human learning from technical legibility.
