# Gate 5 · two additional coordinates in 5D

This directory owns only the approved Gate 5 instrument. It uses Node.js built-ins and browser SVG. No package, lockfile, external asset, WebGL, random seed or deployment is involved. The separately labeled 4D panel is computed from the frozen Gate 3 model definition for comparison; the historical Gate 3 and Gate 4 replay files remain untouched.

The initial candidate is `G5-PENTERACT-001`. Build only after `docs/gate-5/PRESPEC_FREEZE.json` exists:

```sh
node five-dimensional/test.mjs
node five-dimensional/build.mjs
node five-dimensional/builds/<printed-build-id>/server.mjs
```

Open `http://127.0.0.1:43998/` in a supported browser. The page opens paused at zero. The built server serves files from its immutable `builds/<id>/` directory while reading its matching `runs/<run-id>/` records. If the local preview expires, use the exact `node .../server.mjs` recovery command shown by the Run Library. A changed source file requires a new build **and new candidate run ID**; the builder refuses to overwrite a prior run with different source. The `build.json` manifest binds all eight source files, complete SHA-256, frozen prespec hashes, Node version, Git base/HEAD and pinned Gate 3 model SHA-256.

## What the controls do

The `x–w` and `y–v` source turns are independent. The column-vector model applies `Ryv(β) Rxw(α)`, then takes raw xyz. The rotations commute because they act in disjoint coordinate planes. A separate ordinary 3D camera maps raw xyz to SVG positions; its yaw does not enter the 5D projection. All source vertices and edges retain stable IDs through overlaps. At the marked source site, the 4D panel tracks A4/B4 and the 5D panel tracks A/B/C/D.

Task T1 resets to α=β=0 and lets the operator inspect each marked site with **Inspect 4D site** and **Inspect 5D site**. Task T2 resets to zero and supplies the declared route: **x–w 45°**, inspect each site, then **y–v 45°**, inspect each site. The displayed source-action count is from actual successful semantic source changes in this browser session. It is a route count with unequal target cardinalities, not human effort or an optimal path. The cumulative session counters persist through canonical restores; the per-task counter starts anew on a task reset. A task inspection event retains the source IDs and raw projected coordinate of the actual inspected site. Browser-tool clicks, scrolls and failed attempts are preserved separately by the host trace, not inferred by this app.

The rank controls show three known raw-coordinate view sets for a chosen opaque matching ID: base `(α,β)=(0,0)` has rank 3; adding `(90°,0)` has rank 4 and leaves `v` hidden; adding `(0,90°)` has rank 5. The inverse receives only matching ID, measured raw xyz and declared matrices. A separate post-solve evaluator compares to source truth. This is conditional numerical recovery, not screenshot inversion. The generated run also saves all 32 source-ID cases and one non-hypercube `probe` case.

The slice controls act on a separate closed unit 5D ball with known `w=s`, `v=t`. The radicand `1−s²−t²` branches strictly: positive is a solid 3D ball, zero is a single point, negative is empty with no geometry. Presets `(0.5,0)` and `(0,0.5)` have equal radius but distinct known plane conditions. The full xyz projection of the unrotated ball remains a unit ball. Hypercube turns do not drive this slice. The preset point uses a fixed pixel locator, while empty draws no object marker. The SVG circles/curves depict the ball boundary; numerical classification comes from the analytic formula.

Replay runs for 40 seconds with 100 ms model time samples and nine exact checkpoints. Replay from start explicitly restores canonical source, camera, slice, selected ID, observation condition, task and inspector before playing. Pause, one-second Step, Scrub and numeric Seek are separate controls. Seek accepts non-grid and out-of-range seconds; it clamps to `[0,40000]` ms and rounds to the nearest 100 ms. The natural endpoint records `playback.pause`, origin `automatic-playback`, reason exactly `end-of-sequence`. Manual pause has a different origin and reason.

## State and evidence mapping

The model exports `sourceState`, `rotationState`, `projectionState`, `comparatorState`, `sliceState`, `geometryState`, `displayState` and `checkpointState`. The inspector displays full raw 5D source and rotated coordinates, raw projected xyz, separate camera/screen positions, complete grouped source IDs, edge collapse flags, slice conditions, known observation matrices, solver outputs, task status and environmental measurements. `SOURCE5` and `EDGES5` are the ordered source geometry. `comparator4` is the independently computed 4D panel validated against `hypercube/builds/g3-6c31bc16aeca4460/model.mjs`; it never changes with β. `interface` inside checkpoint state binds selected ID, observation condition and task ID/stage. Historical action counters are excluded from checkpoint fingerprints.

File and live state identities use SHA-256. Live state hashes are SHA-256 of UTF-8 `JSON.stringify(value)` for the named exported objects. The source hash binds immutable geometry and version; rotation binds α/β/R and rotated 5D coordinates; projection binds P, raw projected coordinates, raw sites and edges; comparator binds its 4D α-only state; slice binds source equation, two constraints and strict result. Checkpoint also binds quantized simulation time, controls, selected ID, observation condition, task stage, camera and display options. Environment, current playing flag, wall time, session, event sequence and cumulative action counters are excluded. The build's checkpoint hashes are diagnostics; exact replay comparisons are made among repeated states in the same browser/build.

`model.metrics` reports source vertex/edge counts, nonzero projected edges, raw 3D unique sites and collapsed edges. A collapsed edge has Euclidean raw endpoint distance ≤1e−10. Raw 3D and exact 2D screen site grouping use coordinatewise tolerance ≤1e−10 with first encountered source ID as representative. `coincidentMarkerExcess` is vertex count minus exact screen-site count. `glyphOverlapPairCount` and `glyphOverlapPairs` count/list unordered screen-center pairs strictly less than 8 SVG units apart for radius-4 markers. Those are declared screen-space proxies, not perceived occlusion. All drawn vertex glyphs use radius 4, including highlighted IDs; highlighting changes only color.

The live `#state-json` and `/api/activity` observed snapshots include actual viewport width/height/DPR and rectangles for all three scene SVGs, visibility flags, document width and inspector state. Measurements are refreshed on each observation plus resize, scroll, inspector toggle, visibility return, DPR resolution changes, 60 startup frames and every 250 ms while visible. The fixed model viewBox is `640×420`, center `(320,210)`, scale 80 SVG units per raw-3D unit; browser CSS can scale the SVG rectangle. The host captures original browser images and dimensions separately.

The append-only `/api/activity` events are **actual browser UI events**, with `actor=unspecified-ui` and origin `manual-control`, `programmatic-restore` or `automatic-playback`. They are distinct from generated `runs/<id>/events.jsonl`, which is labeled a planned fixture. App event names map to the frozen record contract as follows: `task.reset` and `task.inspect` are the task boundaries; `comparison.source-turn` is a source rotation caused by a T2 button and carries the same before/after source angles as `source.rotation.set`; `observation.compare` selects a rank mode; `replay.start` is the clicked manual replay reset followed by `playback.play`; `replay.open` is only the programmatic paused page opening. The clicked checkpoint/reset/seek/step events carry requested, clamped and actual quantized time. Each observed event includes before/after scalar metrics and named hashes. Full pair IDs remain in the inspector and task evidence; scalar event records avoid inflating the append-only log.

The run's immutable expected records include `initial-state.json`, `checkpoints.json`, `events.jsonl`, `observation-cases.json` and `slice-cases.json`. `activity.jsonl` is created only by actual browser interaction. Root's `evidence/gate-5/` originals, action trace and review packet are separate. No generated record claims human understanding or measured ease of use.
