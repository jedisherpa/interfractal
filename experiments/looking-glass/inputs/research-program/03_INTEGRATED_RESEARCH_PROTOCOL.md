# Integrated protocol — staged, versioned and testable

**Current framing, v0.3:** [Shared-meaning amendment](07_SHARED_MEANING_AMENDMENT.md) is the new starting point for future work. The additions are a planning revision and have not received the independent review recorded for v0.2; earlier reports and results remain historical evidence.

**Scope of the new bench:** prepare partly overlapping input packets, freeze independent snapshots, compare, allow bounded exchange, and test unfamiliar cases. This agent feasibility work precedes human efficacy claims. The v0.2 B/C human comparison and its primary capability endpoint remain unchanged pending an explicit prospective amendment. Shared-meaning, difference-recovery, and transfer measures enter task development as separate outcomes.

Status: research design v0.2 after challenge review, not preregistered and not yet a human-ready instrument. This document resolves the independent R1 proposals into an execution order. R1 evidence remains unchanged.

## Decisions from the independent pass

| Decision | Why | Deferred alternative |
|---|---|---|
| Primary comparison: B plain structured workspace versus C the same workspace with the visualizer available | Identifies incremental practical value of the visualizer while holding protocol and evidence constant | Full protocol × representation factorial, useful later but requires more independent teams |
| Capability is primary in a later efficacy trial; representation accuracy is primary in the earlier usability/measurement work | Keeps the research aimed at joint action without treating a permission ledger as capability | Composite “coherence” score rejected |
| Four-person initial fixture, self-authored contributions | Compatibility with existing code and a small exhaustive task key; avoids confounding lens scaffolding with rendering | 3/5/12 participants and prescribed/hybrid lenses are separate later studies |
| Begin with deterministic imported traces and labeled synthetic model outputs | Makes source omission, misattribution and view parity reproducible | Live LLM synthesis after exact input/output provenance works |
| Use plain, relationship, temporal and outward-interface views | Each answers a distinct user question | Optional 3D/Hopf lab enters only after its mapping and usability are demonstrated |
| Test corrections and leadership mechanisms separately from representation | Avoids a treatment that changes protocol, rights, instruction, lenses, AI and graphics simultaneously | Coordination reviewer’s correction-channel manipulation remains a later mechanism study |
| No universal minimum group size, “flatness” threshold, or topology claim | Neither source evidence nor code establishes one | Formal and empirical comparisons remain open |

## Stage P0 — freeze constructs and competing claims

Inputs: current user corrections, source manifest, independent R1 memos and their access limits. Outputs: charter, definitions, typed records, change log, and explicit competing explanations.

Competing explanations for a positive result include better access to information, extra attention/training, novice scaffolding, attractive grouping, a dominant expert, competent facilitation, more person-time, and actual interaction mechanisms. Each claim below needs a different test:

- Situated capability: the group can do something that one participant with their own resources cannot.
- Interaction advantage: interaction improves a result relative to a prespecified resource-matched independent/nominal group.
- Institutional advantage: an arrangement improves on a competent alternative coordinator or institution.
- Representation advantage: the visualizer improves outcomes relative to a capable plain representation of the same process/evidence. Comparable usability is a design goal to evaluate, not an assumed fact or a post-result inclusion rule.
- Compression adequacy: a group-level interface retains enough information for specified external requests and perturbations.

Gate: review resolves ambiguous meanings that change scoring or permissions. A disagreement about ontology can remain open if it does not change an operational claim. Do not wait for a theory of consciousness to test task legibility.

## Stage P1 — semantic and measurement bench

Inputs: P0; frozen source adapters; synthetic cases. Required outputs: deterministic event model, readable B baseline, C visualizer adapter, exact input/output manifests, source-linked inspection, replay parity, and independently checked task keys.

Bench cases must cover: decisive round-two revision; model-attributed agreement without human endorsement; stale response; missing response; explicit disagreement; out-of-scope representative; changed resource availability; identical outward summaries with different dependencies; camera-induced overlap; participant-ID relabeling; source corrections; overlapping group membership; and 3/4/5/12 rosters. Every observation is labeled as user statement, task stipulation, inference, projection, or measured result.

Advancement requires zero unresolved consequential source loss, false attestation, stale-version action, or permission change caused by rendering in these cases. Every plotted property must have an inspectable meaning, and every important fact must be retrievable in B and C. Each view must work with keyboard and a plain fallback. This is a bounded acceptance corpus, not a proof against every possible failure.

Current executed evidence: studies/verify_fixture.py enumerates 32 specified synthetic plan-state combinations, separates physical feasibility, authorization and readiness for four proposals, and checks summary-insufficiency counterexamples for readiness and a shared physical resource. It does not exercise B/C software or a predictive dynamics model. Therefore P1 is incomplete even though the fixture checks pass. Before instrument acceptance, extend the corpus to missing actors, explicit refusal, stale mandates, unauthorized routes, missing proposals and corrected sources; this task scorer is not a general authorization engine.

After faithful records and suitable measures exist, the program branches. Visualizer efficacy proceeds through P3. Capability, interaction and collective-interface research can use the plain workspace and proceed through the relevant P4/P5 feasibility and design gates without a positive P3 result. Synthetic compression cases can develop earlier. This prevents a negative graphics result from blocking the owner's central research question.

## Stage P2 — cognitive interviews and usability/measurement pilot

Purpose: test whether terms, controls, logs, task difficulty and scoring work. No efficacy claim.

Proposed sequence: first 4–6 adult individual cognitive interviews covering different levels of geometric/software familiarity; then a planning envelope of 8–12 intact four-person teams balanced across B/C. These are coverage/budget starting points, not a statistical justification. Confirm the count against feasibility precision and recruitment constraints before collection. Use new participants after material redesign.

Team condition stays between groups. Use nonidentical, reviewed task forms; counterbalance their order within each condition. Within-person interface exploration may occur in separate formative interviews, but those observations do not estimate the causal B–C team effect.

Compare retrieval of exact contributions, understanding of dependencies, recognizing missing versus dissenting views, interpreting delegated scope, and tracing outward claims inward. Record time, correction success, unsupported inferences, and accessibility failures. Collect brief private reports about ability to contribute/correct/disagree/decline; these questions require cognitive testing and are not a validated agency scale.

Provisional feasibility criteria to ratify before recruitment: at least 90% of scheduled submissions technically recoverable; at least 80% of participants complete the core tutorial without live rescue; no unresolved critical false-attribution or action-permission defect. Freeze whether aborted sessions contribute scheduled submissions to the recoverability denominator and distinguish technical capture from participant completion; report both. Report numerators, denominators and intervals, including results by condition. Small-sample percentages are diagnostic, not assurance. Qualitative failure can block advancement despite favorable percentages. Task ceiling/floor effects, ambiguous keys or condition-dependent scoring trigger redesign.

The cognitive review proposes a 3-relationship × 4 surface/relation recognition battery. This program develops that battery during P1/P2; it is not yet a delivered validated instrument. Three relationships: complementary information, cross-part dependency, and collective output retaining internal differences. Four cells: similar/different appearance crossed with preserved/changed relation. Include insufficient-evidence answers and avoid teaching that visual similarity is always misleading.

## Stage P3 — confirmatory visualizer comparison

### Intervention and estimand

B: plain structured workspace with readable cards, typed relationship lists, timeline, source links and correction/attestation controls. C: the same evidence and operational capabilities with coordinated visual views available. Neutral interface names. Equal devices, total task time, tutorial duration, communication opportunity, facilitation, task updates, ability to inspect and correct, and access to evidence. C may add navigation cost; that cost is part of the practical effect, not erased afterward.

This estimates the effect of being offered the visualizer on top of the same capable workspace. It is not a pure test of geometric encoding with every interaction identical. A later tightly matched rendering-only experiment can isolate that narrower effect. AI assistance is absent or fixed identically in both conditions for the first trial; live AI is a subsequent factor.

Before allocation, freeze B's controls, C's opening/default view, how C users retain access to the plain view, switching behavior, and the exact equal-duration tutorial sequence. Residual proficiency differences are part of the offered package. C's effect includes adoption under this onboarding, not just performance among willing users. Archive screenshots and executable versions.

Population: eligible adult four-person teams under a specified familiarity/recruitment policy. Primary estimand: difference C minus B in team-mean objectively scored task performance across a frozen battery of novel initial-and-revision tasks under fixed time, analyzed by assignment. Generalization is bounded by population, task bank, interface versions and setting.

### Endpoint and scoring

Primary: physical task-quality score averaged at team level across the frozen battery. Capability points derive only from task constraints, costs or quality. Mandate accuracy, consent, representational accuracy and participant experience are separate outcomes. The lantern fixture's 8 probes are a calibration bundle and may not be reused as an undifferentiated primary capability score.

The R1 methods memo provides a separate repair-event fixture with a 0–20 physical score; use it as a task-development template, not a validated battery. Before registration, independently enumerate all task answers, establish item difficulty, freeze time limits and compute the exact primary scoring function. A skipped answer by a participating team at deadline can score zero under a frozen rule. Lost outcome recordings and data unavailable after withdrawal require missing-data handling. Documented tool-caused inability to finish may instead be an observed failure; follow the prespecified event strategies below.

Define the intended task domain before selecting forms: complementary information, resources/skills, revision, uncertainty, coordination cost and outward dependency. Log task inclusion/exclusion reasons. Use display-agnostic reviewers and preserve novel held-out forms never used for interface tuning. Include boundary tasks where a competent individual/coordinator or direct communication should suffice. Freeze task weights, range, distribution and a fixed task denominator; do not quietly average only surviving tasks. Randomization cannot make a hand-picked battery representative of all collective work.

Secondary: appropriate revision, recovery time, effort, accurate dependency forecast, retrieval of another person's different view, false agreement/authority attribution, correction burden, and private participation reports. Report individual distributions and role disparities alongside team averages. Perceived unity and confidence are descriptive outcomes, not capability substitutes.

### Allocation and analysis

Randomize intact teams after baseline measures; conceal allocation generation and use few justified strata (e.g. familiarity and baseline task skill). Balance facilitators across conditions and use scripts. Outcome scorers receive plain exports without condition labels where feasible. Masking success should be checked. Repeated tasks/clicks do not increase the number of independently randomized teams.

Prespecify the team-level primary contrast, uncertainty interval and any adjusted analysis. Task-level mixed models are optional only with explicit team dependence and task/order terms; avoid unsupported random-effects complexity in small samples. Use team-aware uncertainty for individual outcomes. Do not control the primary treatment effect for post-assignment proficiency, expectation or visualizer usage. Preserve assignment-based inference; usage is a secondary descriptive/mechanistic analysis.

### Sample planning and decision rules

Before comparative data, select a smallest worthwhile task benefit δ on the actual score/time scale and a maximum tolerable decrement h on a clearly defined participation/representation outcome. Define the confidence level, multiple-claim error control, risk tolerance for false attribution, and treatment of missing data. These are not yet fixed. Their absence prevents confirmatory launch, not continued task and instrument development.

Plan the number of independent teams using plausible between-team variation, within-team task correlation, task ceilings, attrition and the precision needed for both benefit and tolerable-harm decisions. Use several variance assumptions. Pilot treatment effects are too unstable to be the sole input. Choose justified design alternatives Δdesign greater than δ, and calculate the probability that the lower bound exceeds δ, not merely that a test rejects zero. Separately and jointly simulate the participation bound and report inconclusive probabilities. Specify the multiple-claim error rule; a well-powered task effect may leave harm uncertainty unresolved.

Proposed decision framework, to freeze before registration: let larger participation scores mean better participation and let L/U denote the prespecified uncertainty bounds. Define attribution incidents, event denominators, follow-up window and tolerated incidence separately; zero observed incidents is not evidence of zero risk. Apply the following categories in order and report the underlying outcomes even when more than one concern is present.

| Category | Proposed condition and consequence |
|---|---|
| Harm concern | A prespecified critical incident boundary is crossed or participation evidence indicates decrement greater than h (e.g. U below −h); pause/revise the affected use |
| Worthwhile benefit excluded | Task-benefit U is below δ; do not advance a worthwhile-benefit claim for this setting |
| Advance to broader visualizer evaluation | Task-benefit L exceeds δ, participation L exceeds −h, incident bounds meet their rule, and missingness sensitivity does not overturn the decision |
| Otherwise inconclusive | Every remaining case, including positive effects straddling δ or task benefit with unresolved participation harm; gather justified evidence or prefer the adequate plain option |

The rule requires all advance criteria jointly. Boundary conventions, confidence/error rules and numerical tolerances remain P3 planning decisions. No optional stopping when results look favorable; any interim looks need a prior rule. This visualizer decision does not govern whether capability/interface research may continue.

### Withdrawal and missingness

Record losses, timing and voluntary reasons. Do not replace a person mid-trial and call the team unchanged. Analyze all retained, authorized observations by original assignment; report unavailable outcomes and sensitivity analyses under explicit assumptions. Do not impute refusal as assent, disagreement as failure, or missing evidence as a negative opinion. Define data-deletion limits before enrollment.

Distinguish lost recording of an outcome from tool-caused inability to finish: a C crash that causes a documented missed deadline may be an observed package failure in this practical estimand. Prespecify separate strategies for recording loss, interface interruption, outside interruption, participant withdrawal, team dissolution and resumed work. State when the intended four-person endpoint becomes undefined. Missing observations need explicit bounds/sensitivity analyses; assignment labels alone do not remove attrition bias.

## Stage P4 — mechanisms and competing arrangements

After relevant measures and source fidelity work, investigate one added factor at a time or a powered factorial design: prescribed/self-authored/hybrid lenses; guided analogical comparison versus equally timed separate examples; correction-channel design; centralized versus distributed stewardship; optional 3D versus 2D; 3/4/5/12 participants. These studies require their own feasibility and inference plan, not a favorable visualizer trial. Keep basic participant rights and functional access intact in all arms. Test contexts where a knowledgeable coordinator is efficient and where low-status corrective evidence is indispensable.

A separate interaction-advantage study uses the same number of independent solvers, complete information, devices, training and person-time as the interactive team, with a prespecified aggregation rule and charged aggregation cost. Report elapsed time and person-time separately. Retrospectively choosing the best independent answer is a strong oracle benchmark with a selection advantage; label it and also include an implementable aggregation rule if practical deployment is the claim.

## Stage P5 — cross-scale participation and durability

Use multiple groups over repeated sessions, with a genuine dependency between an outward group offer and other groups' actions. Export capability, limits, representative mandate, uncertainty and exception pointers. Introduce external changes; observe whether feedback reaches the correct internal contributors and revisions propagate back outward.

Use a plain interface if appropriate; P3 visualizer benefit is not an entry requirement. For each compression claim, state the observable, prediction horizon, external-input range and allowable loss. Evaluate summary-only predictions separately from predictions after permitted drill-down, charging retrieval and communication cost. Source access does not itself establish predictive adequacy. Include physical resource/dependency counterexamples as well as permission cases, held-out external requests and important worst-case failures. An exact controlled coarse-dynamics claim has the stronger closure obligation in the mathematics memo; an approximate task interface need not satisfy it universally.

For durability, define a viable capability region, perturbation, observation interval and recovery criterion before collection. Recovery may use a new arrangement while restoring the outcome; it need not restore the previous shape. Record stewardship actions, failed handoffs and substitution. Authored snapshots establish no residence time or metastability.

When groups interact within a federation, randomize at the federation level or explicitly model interference; constituent groups are not independent treatment units. Compare accurate compact interfaces against equally available full detail and naive summaries. Test predictive loss, coordination cost, missed dependencies, unauthorized overcommitment and recovery. Include overlapping memberships and turnover rather than imposing a universal tree. A snapshot cannot establish long-term stewardship.

## Human-study readiness and records

The responsible study owner determines applicable institutional/ethics review, recruitment and consent requirements for the actual setting. Use low-stakes fictional commitments and consenting adults initially; children, employees under dependent relationships, and consequential real agreements are outside the initial plan. Do not call this package a registered or approved study.

Before enrollment freeze: study owner/contact; recruitment and compensation; information sheet/consent; what peers/researchers see; pseudonymization; retention/deletion; withdrawal handling; accessibility; session stopping; incident response; and current instrument/task versions. Audio is optional only with a stated need and separate consent; avoid intimate self-disclosures. Default public research outputs are synthetic traces and aggregates.

Stop an affected session for requested withdrawal, distress, harassment, inaccessible essential controls or false attributed commitments. Pause collection for a reproducible consequential attribution defect or serious privacy incident; repair and independent verification precede resumption. These are study-design duties, not a new approval barrier for the present read-only research.

A planned fictional error probe is different: tell participants that task examples may contain mistakes, present the false interpretation in a separate labeled suggestion/probe panel, and preserve the accurate canonical source record. Fictional characters' stipulated endorsements are not live participants' actual assent. An unscripted real-person misattribution, corrupted canonical record or created action right still triggers the defect rule; it cannot be excused afterward as a probe.

## Preregistration checklist and limits

Before P3, timestamp/register the actual protocol, hypotheses, population, intervention versions, task bank and keys, primary contrast, δ/h and uncertainty rules, team/sample rationale, allocation, exclusions, missing-data analyses, stopping rules and deviations policy. Registration is not done by writing this checklist. Preserve exploratory analyses as exploratory.
