# Gate 9 matched-observation instrument

Candidate `G9-MATCHED-001` implements the frozen Gate 9 five-file prespec with Node built-ins and browser HTML/SVG. The first immutable build is made by `node matched-observation/build.mjs` from the Looking Glass root. Launch only its reported `builds/g9-…/server.mjs` on loopback port 44002. Browser route `/` opens the paused canonical tour at second 0. No external package, answer service, participant system, or write API is used.

The exact model and canonical JSON live in `core.mjs`; `engine.mjs` handles accepted/rejected events, two-choice sealing, registry, conditions, manual review and tour checkpoints. Canonical JSON recursively sorts object keys, preserves array order, emits no whitespace, and stores reduced rational strings. SHA-256 digests its UTF-8 bytes. The camera fixes yaw at 0° and pitch at +20°: display horizontal = `140 + 80 x`; display vertical = `100 - 80 (y cos 20° - z sin 20°)`. SVG uses a 280×200 drawing in the same observation-card component for choose, watch and static. No autoscaling or interpolation occurs. Exact rational coordinates and two-decimal labels are both displayed; negative zero is normalized to `0.00`. Cards wrap at narrow widths and may require scrolling; equal source data does not assert equal simultaneous visibility or legibility.

The browser inspector is `#inspector` and the complete JSON export is `#export-output` after **Export completed route**. An unfinished watch inspector contains only acquired occurrence outputs, public common context, and trace identity; its final compatibility summary and full trace payload appear only at completion. The completed export includes the selected trace, accepted choice-event references, all retained sealed registry entries, current route summary, and event log. Each route must be actually completed before its own export; the app never manufactures other route completions. Event-log export is a read-only control and is separate from the completed-route export.

The frozen tour has 24 nominal simulation seconds and 10 direct checkpoints. Its 12 scheduled semantic events are separate, including choice then seal at 4, and condition select then play at 6 and 14. Local watch and static clocks each run for 6 nominal seconds. Manual pause, restart, step and sheet completion mark `manual-review`; natural uninterrupted completion remains `standard-playback`. Only one timer is active. Browser controls are labeled for software validation; `user-control` means UI origin, never a human participant identity. The public source table and C02-W02 reference are disclosed in every condition. Selected-record compatibility is a transparent computation, and human performance remains untested.

`node matched-observation/test.mjs` checks all nine ordered choice pairs, independent expected hashes and records, the repeated and insufficient cases, rejection, route derivation, manual completion, canonical event chains and paused restoration. The immutable run stores `run.json`, `initial-state.json`, `events.jsonl`, `checkpoints.json`, and `computational-results.json`. Existing candidate bytes are verified, never rewritten. The server exposes only listed assets, run read endpoints, and the closed review allowlist. Missing review files return 404 until the host writes them.
