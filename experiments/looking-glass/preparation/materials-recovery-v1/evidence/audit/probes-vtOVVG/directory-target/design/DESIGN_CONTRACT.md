# Materials v1: finite evidence, preserved differences

This is a preparation design for later research, not a four-agent run, human study or Gate 14. The actual user deferred both agent and human collection. Eighteen authored fictional cards and exact tasks make source fidelity and task-local inference independently checkable; they do not define universal word meaning. Engineering Astra/Sol workers author, package and audit these materials. They are not the four future research participants. The independent key review is procedurally blind in a shared workspace, not OS-enforced isolation.

## Inputs and release boundary

The stable review inputs are world.json, allocations.json, development-tasks.json, withheld-tasks.json and snapshot.schema.json. world.json contains exactly C01–C18 at cutoff tick 10. C01/C02 are shared anchors; four disjoint blocks of four cards yield four six-card packets. Top-level rules/statusSemantics and entities/plans duplicate only those two anchors. Participant builds must not copy other card facts into shared metadata. Every source card and claim retains its ID, version, timestamps, source kind and directed argument roles. C12 explicitly supersedes C11's capacity claim; C14 restates C13's commitment lineage without adding quantity.

Initial participant allowlist: own filtered world; own allocation; D01–D08 only; snapshot.schema.json; PARTICIPANT_INSTRUCTIONS.md; exact initial prompt and safe settings/input manifests. No full allocations listing, peer cards/outputs, union world, AUTHOR_ANSWER_KEY.json, withheld-tasks.json, researcher plans or this contract. Participant-visible manifests pin only their own delivered files and common settings, not private filenames or private content hashes. Researcher inventories pin all artifacts separately. Researcher local access is not a promise that an exposed HTTP route can safely serve it; the preview allowlist must keep keys and withheld cases off every route, query and directory listing. Viewing the researcher full-union preview is exposure, not a blind participant condition.

Withheld-tasks.json contains six tasks in seven independent contexts. Release it only after all comparator final artifacts are frozen, and log that boundary. Never release the author key to participants. The schema contains no answers. Source/task files, rules and questions must be frozen before an independent auditor derives answers without reading the author key. A disagreement becomes a recorded finding and, if substantive, a preserved revision; never silently rewrite frozen material.

## Finite model and intended distinctions

R01–R10 are the operative rules. Four-valued statuses encode positive/negative evidence independently: supported=(1,0), refuted=(0,1), conflicted=(1,1), unknown=(0,0). Conjunction has positive support only when all conjuncts have it, and negative support when any has it. Preserve all component statuses. Thus an unknown capacity combined with a conflicted inspection can refute positive readiness without making every component false. Only supported readiness is eligible for a proposed action. No actual dispatch occurs.

An exact plan version binds requirements and grants. A grant does not create capacity, imply endorsement, or bind another actor. Inspectors can disagree without a hidden priority rule. A model attribution is a different predicate from a fictional actor's stipulated endorsement. Dev's complete mandate permits description, not commitment. Sources and their restatements count once by ID/lineage; shared anchors repeated in four packets remain one source.

The three mutually exclusive development plans have (output,cost) P8=(8,4), P12=(12,7), P10=(10,6). Their explicit dependency lists, old/new requirements, alternative grants and physical capacity records determine answers. "Ready." has different directed relations in C06 and C13; C13/C14 express the same commitment through different surfaces. These are authored contrasts, not measured semantic similarity. Initial scope answers use only each packet; post-union answers use all eighteen cards. Unsupplied facts stay unknown; no packet is required to reconstruct the union.

## Snapshot and validation contract

snapshot.schema.json defines syntax. Additionally check: unique snapshot/card/interpretation/task IDs; exact six-card initial membership; sourceCoverage is a bijection onto suppliedCardIds; initial task set exactly D01–D08, union/final task set exactly D01–D10; every values/evidence map has exactly that task's atom keys; task value types/enums match task definitions; every reference resolves to a supplied claim or public rule; no unseen/superseded claim silently supplies a current fact; confidence is optional model self-report; no action is enacted. Initial phase has no parents. Revised phase names its immutable initial parent, exact trigger inputs, changed interpretations and retained dissent. Synthesis identifies all included snapshot versions, never substitutes initial versions for revised ones.

Unknown, private/withheld, not asked, declined, withdrawn and conflicted are distinct reasons. This finite corpus includes unknown, explicit decline and conflict; it does not fabricate private or withdrawn events. Record a reason in unknowns/missingDependencies, and use refuted only for explicit negative support or a derived violated constraint. Human attribution is not available in this schema: confirmationStatus is always model_generated_not_human_attestation, even when quoting a fictional source stipulation.

Interpretations are solver records with versions; source claims remain immutable. Raw output, parser result, schema failures and attempted/completed status stay separate. Retries after a malformed output are additional charged attempts, not overwritten successes. Schema validity is not source correctness; source correctness is not human understanding.

## Equivalent plain and visual preparation

Both proposed views consume the same normalized record and expose the same source/version inspector, typed relation list, missing/conflicting evidence, original/revised snapshots, task values and exports. The plain workspace is usable independently. Visual nodes/edges map to explicit typed IDs; position is layout only. No distance/centroid infers agreement, mandate or truth. A comparison row identifies both source scope and record version before reporting disagreement. A changed layout cannot change derivations or permissions. Record displayMappingVersion and rendering build separately from semantics.

This material packet does not deliver or accept the integrated instrument. Its future acceptance must use labeled synthetic imports and actual browser actions, preserve failures, verify parity and source/version behavior, and test the critical workflow before polish. No new geometry study is authorized here. Withheld tasks and keys stay outside participant-facing instrument routes.

## Review and use

Read execution-plan.json, PROMPT_TEMPLATES.md and SCORING_AND_ANALYSIS.md as researcher-only proposals. Model/settings and budgets are explicit proposals pending launch preflight and future authorization, not ratified or executed sessions. Initial isolation requires fresh contexts with only the exact serialized bundle, tools/network disabled, or an equivalently restricted runner. Same-workspace agents with filesystem access cannot be called isolated. A failed access/context/version check prevents launch; never silently truncate the union or pretend unavailable model settings were applied.

Preparation acceptance requires independent source/task/key reconciliation, deterministic bundle/manifest tests, privacy-boundary tests, schema validation and an explicit inventory of remaining instrument/human-protocol work. Future collection, human approvals and efficacy findings remain deferred. A successful finite key check certifies these stipulated distinctions only.

The common observation window is all supplied records through tick 10; no future prediction horizon or durability interval is asserted. Readiness is a current conditional task classification, not an observed future dispatch. The POOL artifact is a lossless envelope containing the original valid snapshots and a scalar readout; it is not a newly authored snapshot falsely claiming a single evidence scope. The schema pool phase is reserved for a future separately specified normalized pool record, not used by this proposal.
