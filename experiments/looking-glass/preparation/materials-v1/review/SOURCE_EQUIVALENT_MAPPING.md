# Source-equivalent plain and visual mapping

**Preparation specification; implementation and acceptance pending.** This maps [the frozen contract](../design/DESIGN_CONTRACT.md), [world](../design/world.json), [snapshot schema](../design/snapshot.schema.json) and [tasks](../design/development-tasks.json). It adds no new source facts, scored answers, dimensions or research condition. Candidate 001's browser overview is a source-inspection page, not an implementation of the comparison workspace below.

Both representations must consume the same access-filtered source set, source versions, cutoff, snapshot versions and typed claims. A researcher may inspect all eighteen cards. An initial participant has exactly the assigned six plus shared definitions; changing representation cannot disclose peer sources, withheld cases, keys or private manifests. An inaccessible dependency is marked missing rather than silently resolved by a full-union backing store. Source ID deduplication is independent of how many times an item is drawn.

## Same information and operations

Required operations in either representation are source/version inspection, predicate/argument inspection, filtering within the authorized set, original/revised comparison, missing/conflict inspection, and equivalent export. Each visual selection has a keyboard and plain-list path. Source-changing corrections are immutable imported/appended records with provenance; this mapping does not authorize editing fictional source facts or submitting real attestations. Both views use the same operation availability and validation result, including refusals. A picture must not offer a “commit” operation absent from the underlying protocol.

Every visible visual property is either a declared record encoding or labeled layout only. Position, distance, clustering, node size, center and camera movement carry no inferred endorsement, authority, agreement or truth. Do not introduce a centroid, consensus region or global coherence score. Relation labels and IDs remain available when color is unavailable. Different navigation effort is plausible; it must be measured later rather than called equal by inspection.

No research snapshots currently exist. An implementation should show that absence honestly. Demonstration snapshots, if separately prepared for software testing, must be labeled synthetic and must not populate participant-result counters. The deterministic pool retains scope-tagged original tuples; its `pool_conflict` is a pooling marker, not a new source-level truth value.

## Bounded future acceptance checks

The dependent instrument review should compare machine-readable information payloads and accessible text across the two views for the same scope/version. At minimum, inspect C04's rejection plus grant, C06/C13's different relations, C13/C14 deduplication, C11/C12 supersession, C16 attribution, C18 conflict, Dev's mandate, and each plan component. Check the same source/export set, keyboard paths, filters/restores and rejection behavior. Relabeling IDs consistently or changing layout must preserve task values, source lineage and permission state. Repeat with an initial six-card scope to test that visual selection and export cannot recover peer/private content.

After the initial/revised workflow exists, compare actual parent versions and synthesis inputs, preserve invalid imports and failed controls, and test the critical workflow in a supported browser before presentation polishing. This is a specification for later preparation work, not a claim these operations or checks have already passed. No human accessibility certification, comprehension, visual benefit or research launch follows from software parity.

## Explicit omissions

This mapping does not provide the integrated instrument, transfer response validator, research runner isolation, human tutorial/consent/readiness documents or the broader acceptance cases for withdrawn/private records and roster changes. Those remain identified preparation dependencies. The current eighteen-card corpus does not contain a fictional withdrawal event; a blank or unknown entry must not be mislabeled withdrawal to make a demonstration appear complete.
