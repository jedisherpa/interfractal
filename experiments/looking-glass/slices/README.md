# Gate 4 slices instrument

This directory owns the Gate 4 analytic 4D-ball slices, fixed orthographic projection, declared two-candidate ambiguity and a separate sampled projection-movie counterexample. It uses Node built-ins and browser SVG only. No external package, lockfile, WebGL or seed is involved. The historical Gate 0–3 instruments remain in their own directories.

## Exact replay and recovery

Run `node slices/test.mjs`, then `node slices/build.mjs` after `docs/gate-4/PRESPEC_FREEZE.json` exists and passes its SHA-256 checks. The builder creates `builds/g4-<source-hash-prefix>/` and `runs/G4-SLICES-002/` with write-once files. The build identity hashes the eight source files listed in `build.mjs` by filename, NUL, byte content, NUL, in order. Each frozen specification file hash is verified before the builder writes a run. To restart the exact tested candidate, use the absolute `node .../slices/builds/<buildId>/server.mjs` command shown by the builder and Run Library. It binds only 127.0.0.1:43997; open `http://127.0.0.1:43997/`. The run opens paused at zero. A changed source requires a new candidate ID and build; do not change files inside a tested build. Candidate 001 remains preserved in `builds/g4-1a289997d9829f9c/` and `runs/G4-SLICES-001/`; its initial browser inspector held a stale DPR until an input rendered the page. Candidate 002 adds a resolution-query listener, a first-paint refresh window and passive 250 ms environment refresh without changing the model equations.

The standalone `runs/G4-SLICES-002/movie-3d.json` contains exactly 401 ordered `{timeMs,center,radius}` frames plus a 3D trace schema/description. It is generated once before browser trials and bound by `movieTraceSha256` in the build and run. The browser fetches `/api/movie-trace`, hashes its exact response bytes, and looks up `frames[round(simulationTimeMs/100)]`; the stored-movie renderer receives no 4D source coordinates or rotation. The analytic side independently rotates the `ball-plus` 4D center and projects it. The held-out −90° control at the 20s checkpoint leaves the stored frame unchanged. It rejects this fixed recording under that control; an adaptive 3D model could agree.

## Fields, fingerprints and events

`model.mjs` implements the frozen equations. `sliceAt` retains raw `levelW`, `sourceCenterW`, `deltaW`, `discriminant`, exact branch `kind` (`solid`, `point`, `empty`), radius (positive, zero, null), and a null center for empty. Its additional `classification` is a display subtype (`center`, `interior`, `boundary-point`, `empty`). The fixed `projection` stores the 3×4 P and raw 3D unit-ball center/radius. `ambiguity.candidates` retain the two stable source IDs, definitions and both initial/selected slices. `movie` retains the known source angle/matrix, rotated center, raw projected center/radius, exact selected 3D frame and numerical comparison. All views share the clock and canonical camera, while the primary source never receives the movie rotation.

File and live state hashes use SHA-256. File hashes cover exact bytes. Live hashes cover UTF-8 `JSON.stringify` bytes in property insertion order: `sourceState`, `sliceState`, `projectionState`, `movieState`, `geometryState`, `checkpointState`, and `displayState`. Source excludes the clock; slice and projection exclude camera and clock; movie binds its own sampled time/frame and source angle, but excludes camera. Checkpoint binds quantized time, all raw states, ambiguity plane, mode, camera and overrides. Geometry includes quantized time. Display includes camera. All deterministic hashes exclude browser environment, wall time, session ID, playing flag, event count and focus. Browser and Node floating arithmetic may differ by a few ULPs, so exact fingerprint restoration is compared within the same browser/build; numeric cross-runtime checks use absolute 1e−10. `sourceSha256`, `sliceSha256`, `projectionSha256`, `movieSha256`, `geometrySha256`, `checkpointSha256` and `displaySha256` in inspector/event records map to the named states above.

`events.jsonl` is a planned fixture, marked `planned-fixture`; it is never a claim of observed actions. Actual UI controls append `observed-ui` events to `activity.jsonl` through `/api/activity`, with monotonic sequence, session/run/build, actor `unspecified-ui`, origin and before/after state/hashes. A clicked checkpoint, reset or seek uses `manual-control`; the initial paused open uses `programmatic-restore`; an automatic end uses `automatic-playback` with exact reason `end-of-sequence`. Replay from start records a manual reset then manual play. The `slice.set`, `camera.set`, `ambiguity.compare`, `source.rotation.set`, `movie.compare`, `display.options.set`, `playback.*`, `checkpoint.restore`, `experiment.reset` and `replay.open` names correspond to the frozen event table. `movie.source-turn.restore` is the manual return to the saved movie angle. Playback is quantized to 100 ms; Step advances 1000 ms, seeks round to 100 ms and clamp to the endpoints. The numeric Request exact time control permits non-grid and out-of-range requests and records requested versus actual quantized time.

The inspector refreshes actual viewport dimensions, DPR, document width, primary `sceneRect`, per-scene rectangles and visibility after scroll, resize and inspector toggle. Candidate 002 also remeasures through a DPR resolution-query listener, the first 60 animation frames and a passive 250 ms timer, because candidate 001's startup DPR changed without a resize event. These measurements are not hashed. Inspector open/closed is a declared display option included in checkpoint/display hashes and reset by a checkpoint; labels and depth cues are fixed on, and paused manual controls support reduced-motion review. For each positive-radius ball, the SVG draws the orthographic silhouette as a filled disc of radius `80*r`, then three great circles of its sphere boundary in the xy/xz/yz planes, each sampled at 65 endpoints and transformed by the same camera equation. Their curves depict the calculated 3D solid's boundary, not the full 4D boundary. A point uses a fixed-pixel location symbol labeled as such; an empty slice draws no slice geometry and says “empty / no points”. Axes are display guides, not slice points. All SVG scenes use viewBox 640×420, center 320/210 and scale 80. The CSS may resize the whole scene but does not fit geometry. Ordinary camera yaw affects only screen coordinates and guide axes.

The generated `run.json`, `initial-state.json`, `checkpoints.json`, `events.jsonl`, `movie-3d.json`, immutable build and subsequent real `activity.jsonl` are separate records. `/api/evidence` and `/evidence/gate-4/` are safe read-only routes for root's actual browser evidence. The preview does not imply public deployment or human comprehension testing.
